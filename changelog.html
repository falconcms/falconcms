v2.8.16 Latest ​

Released: 2026-10-30

Choose where a sticky Table of Contents stops.

Added ​

  • Table of Contents → Sticky → Stop at. The heading where the sticky list lets go. Type the heading's text, for example Conclusion, or a CSS selector such as #comments.
    • When the reader reaches that heading, the list scrolls away with the page.
    • The heading stays in the list.
    • Leave it empty and the list sticks until the end of the article, as before.

Changed ​

  • The end of a pinned Table of Contents. At the end of the article, a pinned list now moves up with the page. Before, it jumped off the screen.

v2.8.15 ​

Released: 2026-10-30

A Comments element for your layouts. Also: one H1 on every single page, and a safer comment form.

Added ​

  • Comments element. The builder has a Comments element. It shows the approved comments of the post being viewed, their replies, and the form to add one. Put it in a Layout Builder Content section and every post that section is used for gets its own comments.
    • Content tab: the heading, the count, the order, avatars, dates, replies, and the form's heading and button.
    • Design tab: colours, corners, typography and responsive margins.
    • After posting: the visitor returns to the comments and sees whether the comment is live or waiting for approval.

Fixed ​

  • One H1 on a single post, custom post type entry or product. With the Page Title Bar showing the title, the bar's title is the H1. With the bar off, or its title hidden, the template prints the title as the H1.
    • Before, a builder post with the bar off had no H1.
    • Before, a product with the bar on had two.
    • In a custom Content layout, use a Title element with the dynamic source Post Title and the H1 tag.
  • Comments and the page cache. A comment you approve, or one that is posted or deleted, shows on its cached page straight away. Before, the cache kept the old list for up to a day. A visitor's "awaiting moderation" notice or form error is never stored for other visitors.
  • Table of Contents. The comment section's headings are no longer listed.

Security ​

  • Redirect. After posting, the visitor goes back to the post's own address. Before, it was an address taken from the request, which could point to another site.
  • Moderation. Before, typing a known commenter's email, or a member's, published a comment without moderation. Now a guest comment goes live straight away only when all of these hold:
    • the same name and email already have an approved guest comment;
    • the email does not belong to a member;
    • the comment has no link.
  • Replies. Only an approved comment on the same post can be replied to.
  • Which posts take comments. Only published posts. A guest must give a name and an email.
  • Spam. A hidden spam-trap field turns bots away. The same comment twice in ten minutes is kept once.
  • Names. HTML tags and invisible or direction-flipping characters are removed. They could make a name look like someone else's.

v2.8.14 ​

Released: 2026-10-30

Sticky that sticks: columns, and the Table of Contents on more layouts.

Fixed ​

  • Column → Sticky. With the row's default alignment the setting did nothing. A stretched column is as tall as its row, so it had nowhere to travel. Where a column sticks, it now keeps its own height and stays on screen beside its taller neighbour.
  • Table of Contents → Sticky. Some layouts put the list in a column beside an intro, with the article in the sections below. The list left the screen with its short section, even with the column's own Sticky switched on. Now it pins to the screen until the article ends.
  • Table of Contents → Sticky. A column counts as "beside the content" only when the headings it lists are in the same row.
  • Table of Contents → Sticky. A pinned list sits below a sticky site header instead of behind it.

v2.8.13 ​

Released: 2026-10-30

Fixes for the Table of Contents, the Content element and pages that scrolled sideways.

Changed ​

  • Accordion. A panel slides open and shut instead of appearing all at once.
  • Table of Contents → Sticky. A list in a column of its own beside the content sticks its column, as before. Anywhere else, in a section of its own above the article or on a phone where the columns have stacked, it now pins to the top of the screen once it scrolls past and lets go when the article ends. A collapsible list folds to one line while pinned.

Fixed ​

  • The Content element runs every element in the post. Shown through a Layout Builder Content section, a post's Table of Contents did not appear, and the Accordion, Tabs, Table, Code Block and other elements that need a script did nothing.
  • Table of Contents. Sticky did nothing unless the list sat in a column beside the content.
  • Table of Contents. The section being read stays lit, whether the reader scrolled there or clicked its link, also near the foot of the page. Opening a #section link lights that section, and a long list keeps the lit entry in view.
  • Table of Contents. A heading placed straight above the list ("Table of contents") names the list. It is no longer counted as entry 1.
  • No sideways scroll bar. Several things widened the page. On a phone this showed a sideways scroll bar and a blank strip on the right:
    • Scroll Motion's Slide in from the left / right
    • entrance slides
    • a full-width Content section (on desktop it was a scroll bar wider than the page)
    • long unbroken text in a post
  • A blog post has its title as its H1 again when the Page Title Bar is switched off or hides its title. Before, such a post had no H1 at all.

v2.8.12 ​

Released: 2026-10-29

Folders for the media library, everywhere files are uploaded.

Added ​

  • Media folders. Organise the library into folders, and folders inside folders — on the Media page, the upload page and the media window that opens from pages, posts, the builder and settings. Make a folder at the top level or inside another ("Where"), also right beside Upload to; rename it any time; move it into another folder or make it a main folder again (drag it, or use its Move button — the way on a phone). Move files by dragging them onto a folder, with Move to folder under Bulk actions, or from a file's details, and upload straight into a folder. See Media Library → Folders.
  • Folders only group files: a file keeps its address whichever folder it is in, so no page that shows it breaks, and deleting a folder never deletes a file (its files go back to Uncategorized, its folders move up one level).
  • The media window works on a phone: its Upload / Library tabs show across the top, and its folder filter and search now work (they were placeholders before).

Fixed ​

  • The cart badge stays round with a two-digit count (15 was a pill).
  • The admin bar stays on one line on a phone ("CMS Site" and "Howdy, …" wrapped onto two).

Updating ​

  • A new table holds the folders (cms_media_folders, plus folder_id on media); the update runs its migration. Until it has run, the library and uploads keep working without folders.

v2.8.11 ​

Released: 2026-10-29

One pagination, the same and tidy on every page of the site.

Changed ​

  • One pagination everywhere. The blog, categories and tags, custom post type archives, the shop and its categories, search results, builder post grids and the shop account's orders each had a pagination of their own, and the shop's showed Laravel's default with a "Showing 1 to 12 of 13 results" line squeezed beside it. They now all show the same one: rounded buttons in the theme's primary colour, Previous and Next, the current page filled, long runs shortened with "…", and on a phone only the pages next to the current one, so it never wraps onto a second line.
  • A theme's or a plugin's plain $items->links() renders it too on any page outside the admin, so custom themes match without changes; the_falcon_pagination($items) renders it anywhere. The admin keeps its own. To change the colour, set --falcon-pg-accent on a parent.

v2.8.10 ​

Released: 2026-10-28

A cart of several products no longer breaks the site with 502 Bad Gateway.

Fixed ​

  • No more 502 Bad Gateway with a full cart. The cookie that keeps a shopper's cart between visits held the whole cart (names, prices, picture links), encrypted. After a few products it outgrew the web server's buffer for response headers, and nginx answered every page of that shopper with 502 ("upstream sent too big header"). The cookie now holds only each line's product, variation, quantity and custom fields; names, prices and pictures are read from the shop when a returning browser gets its cart back. A cart too big even for that (about 18 lines) stays in the session, so the headers always fit nginx's default 4 KB buffer. A browser that still has an old, large cart cookie gets its cart back and a small cookie in its place.

v2.8.9 ​

Released: 2026-10-28

Write with AI, free: Falcon AI writes whole articles in the post editor with Claude, OpenAI or Google Gemini (which has a free tier). Also shop hooks for plugins, and cached pages that no longer break add to cart.

Added ​

  • Falcon AI (free, bundled, on by default). A Write with AI button beside the Page Builder tab of the post editor:
    • Give a topic (plus an optional focus keyword, audience, length, tone and notes) and get an outline you can edit, then the article, written section by section as you watch, then its SEO title, description, excerpt and tags.
    • Improve selection rewrites, expands, shortens, simplifies or translates the selected text.
    • SEO suggestions (titles, descriptions, image alt text) in Falcon SEO and its Site Analysis.
    • About 80 writing languages, in a searchable list.
    • Works with Claude, OpenAI or Google Gemini on the site's own API key, set under AI → Settings & Usage. Gemini's Flash models have a free tier; new Google AI Studio keys starting with AQ. are accepted. A busy Gemini model (503) is retried automatically.
    • A monthly token limit, a usage record (counts only, never the text) and a choice of which roles may write with AI. Keys are stored encrypted and never sent to the browser, and every AI answer is cleaned before it reaches the editor. See AI Writing.
  • falcon_admin_post_editor_tabs, a hook in the post editor's tab row.
  • Shop hooks for plugins: falcon_product_card_actions (a button on product cards), falcon_shop_settings_tabs and falcon_shop_settings_toggles (a tab of Shop → Settings), falcon_cart_shipping_bar (a line above the cart and in the mini-cart), falcon_shipping_zone_for_country(), and LazyCart.added() / window.FalconShopUx for add-to-cart feedback. Falcon Shop Boost (Pro) is built on them. Documented in Hooks.
  • settings_params in plugin.json: the Plugins screen's Settings link can open one tab.

Changed ​

  • AI writing moved out of Falcon SEO into Falcon AI, and is now free. A saved Claude key and model are carried over on update; SEO → Settings no longer has an AI section.
  • The shop archive's "Add to cart" opens the mini-cart, like product cards elsewhere.

Fixed ​

  • Add to cart on a cached page no longer fails with 419. With static page caching on, a cached page used to hand its first visitor's CSRF token to everyone after them. Each visitor now gets their own token. Pages cached before the update are rendered afresh.

v2.8.8 ​

Released: 2026-10-28

Your own fonts, builder hooks for plugins, an uninstall that keeps a plugin's data, and product galleries that change their picture again with AVIF on.

Added ​

  • Custom fonts (Customizer → Typography → Custom Font). Upload your own font files from the Media Library, one box per font face; the weights are read from each file, and a variable font is offered as a range. A custom font can be chosen in every typography setting, in the builder, and in Motion Visual text.
  • Builder extension hooks. A plugin can add its own settings to the Extra tab of elements, containers and columns (nested columns too), show its effect in the builder canvas, and add attributes to the page markup of what it touches. Documented in Hooks.

Changed ​

  • Uninstalling a plugin keeps its data. Plugins → Delete now opens a dialog: the plugin's files are removed, but its settings and its own tables stay, so activating it again (or installing it again) brings everything back. To delete the data too, tick Also delete all of its data and type the plugin's slug; the dialog says what that data is. Uninstalling several plugins at once never deletes data. A plugin that comes with FalconCMS Pro reappears in the list on the next page load, ready to activate.

Fixed ​

  • Product gallery thumbnails change the main picture again when AVIF is on. With Falcon SEO's AVIF images, library pictures are wrapped in <picture> with an AVIF source; a gallery thumbnail (or a variable product's option) changed the image underneath, but the browser kept showing the first picture. The AVIF source now steps aside once a script changes the picture.

Security ​

  • The repository's GitHub Actions are pinned to exact versions, Dependabot keeps them and the Composer packages up to date, and a security policy says how to report a problem.

v2.8.7 ​

Released: 2026-10-27

Motion Visual — animated dots, shapes, text and pictures across a whole column or container — smooth scrolling for every link to a section, and two SEO fixes.

Added ​

  • Motion Visual (Column / Container → Extra; free). A layer across the whole column or container, behind its content or in front of it, switched on and off with one switch (off puts no markup, style or script on the page, and keeps every setting):
    • Dots drawn on a canvas — how many, size, speed, color, fine lines between near dots, and what the mouse does to them (push away or pull in).
    • Shapes, text and pictures — 39 shapes, your own uploaded images, and text (fill, outline or gradient; sized as a share of the layer, so it keeps its place on every screen). Each item has its own position, size, turn, color, opacity, blur and mouse depth, and one of seven animations: float, drift, rotate, pulse, swing, orbit, bounce.
    • Seven presets to start from (Floating Dots, Connected Dots, Soft Bubbles, Geometric, Blobs, Big Word, Custom), and Main / Accent / Random colors on the builder's own color picker — Random keeps changing by itself.
    • In the builder the canvas shows the real layer, for top-level and nested columns and for containers, with handles to drag, resize and turn each item.
    • Light on the page: shapes animate with CSS alone; one small script, loaded only on pages that have a visual, draws the dots and follows the mouse, and stops while the layer is off screen. Visitors who ask for reduced motion always get it still; tablets and phones can be set to full, calmer, still or hidden.
    • Plugins and themes can add shapes and presets (falcon_motion_visual_shapes, falcon_motion_visual_presets).
  • Smooth scrolling for every link to a section — builder buttons, text links and image links to #section now glide there and stop just under the sticky header, like the landing-page menu. The scroll is measured again on every frame, so images loading on the way or a header that changes size cannot make it miss; a wheel or touch takes over at once. The address bar reads /page/#section.

Fixed ​

  • SEO changes reach cached pages. Saving SEO → Settings, Bulk SEO or a Site Analysis fix now empties the page cache; before, cached pages kept the old head (a new default share image stayed off them until the cache was cleared by hand).
  • Weekly SEO email: "Send a test now" keeps the addresses typed beside it. The button sent to the old addresses and the field came back empty, so the address looked unsaveable.

v2.8.6 ​

Released: 2026-10-24

The core side of Falcon Security 1.1 (FalconCMS Pro 1.4.0): a baseline Content Security Policy, plugin hooks on the orders list and the shop's sign-in form, and signing in that lands on the page you asked for.

Security ​

  • A baseline Content Security Policy on every page. It blocks nothing the builder relies on (inline scripts and styles, fonts, embeds) but stops framing by other sites, <base> hijacking and plugin objects; on an https site it also upgrades plain-http requests. Replace it or turn it off with the falcon_content_security_policy filter ('' sends none). A site on plain http (a local install) is not told to upgrade, so its admin buttons keep working.
  • X-Powered-By is really gone. PHP adds it itself, outside the response; it is now removed from PHP's own headers too.

Added ​

  • Hooks on the admin orders list — falcon_admin_orders_toolbar beside the search, and falcon_admin_orders_columns / falcon_admin_orders_column for a column of a plugin's own. Falcon Security's Check a number and Risk column use them.
  • Other ways to sign in on the shop's account page — its sign-in form fires falcon_login_form_after with 'shop', so a plugin can offer one there (Falcon Security's "Sign in with a code to your phone").

Changed ​

  • Signing in lands on the page you asked for. An admin page opened without a session still answers 404 — the sign-in address stays hidden — but the page is remembered, and signing in opens it instead of the dashboard.

Pro: Falcon Security 1.1 ​

Two-factor by SMS and WhatsApp, OTP gateways (Twilio, WhatsApp Cloud API, Bangladeshi SMS providers), sign-in with a phone code, cash-on-delivery phone confirmation, a fake-order risk score with courier history (Steadfast, BD Courier) and an order blocklist, "confirm it's you", impossible travel, a Content Security Policy builder, a spam guard, known-vulnerability alerts, signed release integrity in the malware scanner, a security score and monthly report, Telegram and WhatsApp alerts, and an agency dashboard. See Falcon Security.

v2.8.5 ​

Released: 2026-10-21

A security release first: every login form now shares one lockout, an endpoint that let anyone check passwords is gone, and emailed links can no longer be pointed at another domain. Plus read/write permissions per menu, the Instagram Feed element, a working custom-field filter for post loops, reading time in any language, and the hooks Falcon News and Falcon Security build on.

Security ​

  • No more password checking without a lockout. POST admin/login/check told any visitor whether an email and password matched — the "funny" login theme asked it on every keystroke — without the sign-in form's five-try lockout: unlimited password guessing, and a list of which emails have accounts. The endpoint is gone; the theme's running button now waits only for both fields to be filled in.
  • One sign-in lockout for every login form. The shop's My Account sign-in signs in any account, administrators included, but had no lockout and no rate limit. The dashboard's lock now lives in LoginGuard, which the dashboard, the shop and plugins' own login forms (the wholesale login) share: five wrong passwords lock the account for 30 minutes whichever form they were typed into, so switching forms buys no extra guesses; an address the dashboard blocked is refused everywhere; too many failures from one address make it wait; the shop form takes 10 tries a minute and gives one message whether or not the email has an account.
  • Emailed links stay on your domain. Password-reset, magic-login and email-verification links are built on APP_URL, so a request sent with another site's name in its Host header can no longer mail a real token on that domain. Analytics also skips requests for host names that are not the site's (scanners and bots on the bare IP were 60% of the demo's visits); add extra domains with the falcon_site_hosts filter.
  • Analytics referrers become links only when they are http(s): a javascript: referrer, which any visitor can send, would have run in the admin's session.

Added ​

  • Read and write, per menu. In Users → Roles, a section with a list and an "Add New" — posts, pages, every post type, products, media, users, forms, and any plugin menu shaped the same way — is now read with the list's permission and changed with Add New's. A role with the list alone sees the rows but no Add New, checkboxes or edit and delete links. Every submenu has its own permission (ticking one Wholesale screen no longer ticks them all), roles saved before keep working, switched-off plugins' menus are left out and keep their grants, and a plugin runs only while the plugins it depends on run.
  • Instagram Feed element (Pro): show the connected Business or Creator account's posts (Customizer → Instagram: the token is checked, stored encrypted and renewed weekly), public posts by link from any account, or pictures you choose. Everything is kept on your site and refreshed in the background, so pages never wait on Instagram. See Instagram Feed.
  • Post loops by custom field. get_falcon_posts() now applies meta_key / meta_value — the Card element's "Posts By: Custom Field" — and plugins can add orderings (falcon_posts_orderby, falcon_post_orderby_options) and preload data for a whole loop (falcon_posts_fetched).
  • Reading time in any language. Words are counted in every script (a Bangla article used to read as "1 min") and in builder content; the Reading Time source takes a label, a reading speed and digits (Bangla, Devanagari, Arabic).
  • Analytics: Referrer column in the visitor log — Google, Facebook, X, another site by domain, or Direct — matched on whole host parts (as a substring, "t.co" credited fast.company.com to X).
  • Hooks for plugins: dynamic content sources (falcon_dynamic_sources, falcon_dynamic_value), admin list columns (falcon_admin_list_columns, falcon_admin_list_cells), builder elements previewed from their own template, and falcon_login_form_after under both login forms. See the hooks reference.

Fixed ​

  • A posts loop ordered by views threw on the front end; an order nobody answers now falls back to the date.
  • The admin loaded a count per menu on every request (about 80 queries); the admin posts and pages "show" routes answered with a server error.
  • SEO page scores were kept for the whole process, so a long-running worker kept showing the first list's scores.

Pro: Falcon News and Falcon Security ​

Released with Pro 1.3.2: Falcon News (view counter, Most Viewed, RSS, Google News sitemap) and Falcon Security (two-factor and passkeys, firewall, malware scanner, temporary access, lockdown, security log and more). See News sites and Security.

v2.8.4 ​

Released: 2026-10-16

What updating to 2.8.3 turned up on falconcms.com and the demo: a plugin update that never finished, a config cache that was still dropped, and Site Health errors from the update itself that stayed critical. Plus a roomier Title editor and documentation for the new builder tools.

Fixed ​

  • Plugin updates that arrived with Pro but never finished. Pro copies its bundled plugins (Falcon Wholesale, Slider, Search Console) in as the site boots, which during an update happens inside Composer's own run, and finishes their update there. When that step failed, nothing showed it and nothing tried again: on the next boot the files already matched. On the demo, Falcon Wholesale's files were 1.0.1 while the site still recorded 1.0.0 and kept offering the update. falcon:update now finishes every active plugin whose files are newer than its recorded version (new migrations, its upgrade step, the new version) in a clean process after Composer, and prints the outcome.
  • The config cache was still lost on update. 2.8.3 rebuilt the caches a site had before the update cleared them, but Composer deletes the cached config even earlier, while it installs, so only the route cache came back. The dashboard updater now notes whether the config was cached before it runs Composer and passes that to falcon:update. From a shell, a route cache that survived counts for both.
  • Site Health: errors logged during the update itself stayed critical. While Composer swaps the files, Laravel can fail to set up its logger and log Unable to create configured logger. The real cause, a file missing for a moment, is inside the exception behind that line, which Site Health did not read. It does now, so the error counts as fixed once the file is back.
  • Site Health: OPcache read "off" when the checks ran from the command line. OPcache is normally off for the CLI (opcache.enable_cli), which says nothing about the web server. From the CLI the web setting now decides.

Changed ​

  • Title element: a taller editor. The toolbar wraps to two rows in the settings panel, which left room for one line of text; a two-line title was cut off. The editor is now 260px tall.

Documentation ​

  • Builder Elements: the Title section describes the rich editor and the H1 default (it wrongly said the element always shows the current page's title); the Item List section covers duplicating and reordering items; and there is a new Table section with pasting, the Cells grid and the row controls. With screenshots from the demo.
  • Upgrade Guide: what falcon:update now does with plugins and caches, and why errors logged during an update clear themselves in Site Health.
  • Media: changing a file's title no longer renames the file.

v2.8.3 ​

Released: 2026-10-16

A rich editor for the Title element, duplicate buttons for list items and table rows, and three fixes found on falconcms.com: images that broke when a file was renamed, the config cache that every update dropped, and Site Health errors that stayed open after an update had fixed them.

Added ​

  • Title element: a rich editor. The Title field is the same editor as the Text Block's, with the tools a heading can hold: bold, italic, underline, strikethrough, text and background colour, link, clear formatting and the code view. Enter starts a new line inside the heading. Paragraphs, lists and tables are left out on purpose, because a heading cannot contain them. Existing titles open exactly as they were saved; a title is only rewritten when you edit it.
  • Title element: new titles start as H1. The HTML Heading Tag of a newly added Title is H1. Titles saved before this release keep rendering as H2, as they always have, so no existing page changes its heading outline. Their tag box now says H2 instead of being blank.
  • Item List: duplicate an item. A copy button next to delete duplicates the whole item (icon, colour, text, link) right below the original.
  • Table: duplicate a row. Each row of the Cells grid has a copy button; the copy lands right below the original, and the header row stays first.

Changed ​

  • Table: drag to sort rows. The up and down arrows in the Cells grid are replaced by a grip: drag a row by it and drop it where it should go; the row under the pointer is outlined. The grip, duplicate and delete controls are now one clean column of matching icons. Only the grip starts a drag, so selecting text inside a cell works as before.

Fixed ​

  • Renaming a media item's title broke the images that used it. Changing the title in the Media Library also renamed the file, so its address changed, and every page, section or setting that showed the image kept pointing at the old address and showed a broken image. The title is now only a label and the file keeps its name, as in WordPress. Files already renamed by an earlier version keep their new name; re-pick the image where it shows as broken.
  • Every update dropped the config and route caches. The update's last step cleared all caches and nothing rebuilt them, so a cached production site ran uncached after each update (and Site Health said Configuration is not cached) until someone ran php artisan optimize. The update now rebuilds the config and route caches the site had before. A site that never cached stays uncached, and a rebuild that fails is cleared rather than left half-written.
  • Site Health: errors an update fixed no longer stay open. An error that surfaced inside Laravel itself (a database insert, for example) or a file that an update moved away was never counted as fixed, because the file it named never changes. It now counts as fixed when new code was installed after it last happened. If it happens again, it is open again.

v2.8.2 ​

Released: 2026-10-16

Fixes from the week after 2.8.1: analytics visits that were lost, two Site Health false alarms, the Cloudflare token you can now recognise, and two hooks the Pro Wholesale plugin uses.

Added ​

  • Cloudflare cache: the saved API token shows half masked. Settings → Integrations → Cloudflare cache shows the first half of the saved token and masks the rest, so you can see which token is in use without the whole token ever going back to the browser. Save the form as it is and the token is kept; click into the field to paste a new one.

v2.6.3 ​

Released: 2026-09-04

Fixed ​

  • The sitemap returned a 500 on any server with short_open_tag enabled. Blade does not read a template as plain text — it runs token_get_all() over the source and applies its directives only to the inline-HTML tokens that come back. Where short_open_tag is On, PHP's tokenizer treats the <? that opens an XML declaration as the start of PHP code, so the rest of the template was handed back as PHP tokens and written to the compiled view uncompiled. Visitors got a parse error instead of a sitemap. The declaration is now assembled from pieces so those two characters never sit together in the file. The template renders identically either way; only servers with short_open_tag=On were affected, which is why it never appeared in local development.
